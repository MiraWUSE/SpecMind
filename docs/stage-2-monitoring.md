# Этап 2: обновление страниц и жизненный цикл мониторинга

## Результат

Страницы переиспользуют свои ViewModel. HardwareInfo уведомляет уже открытые Dashboard, Detailed и Monitoring об обновлении. Мониторинг использует четыре общие коллекции по 60 последних измерений; смена страницы не создаёт дополнительных таймеров и не сбрасывает историю, выбранную категорию настроек или черновик чата.

Сканирование выполняется в фоновой задаче. Одновременные запросы обновления на UI-потоке ожидают один текущий опрос. Ошибка опроса не добавляет пустые точки и не блокирует следующий опрос.

LibreHardwareMonitor Computer открывается один раз. Доступ к нему и закрытие синхронизированы; после Dispose новые чтения отклоняются. При закрытии окна приложение останавливает таймер, снимает подписки страниц, ожидает текущий опрос без публикации позднего результата, освобождает scanner и завершает desktop lifetime.

## Проверка

`dotnet test SpecMind/SpecMind.sln --no-restore --nologo -v quiet` успешно собирает решение и выполняет **7 тестов**:

1. Открытые страницы получают уведомления и новый HardwareInfo.
2. Мониторинг использует общую ограниченную историю, сохраняемую при переходах.
3. Все шесть страниц переиспользуются; категория настроек, история и черновик AI сохраняются.
4. Перекрывающиеся обновления используют один опрос и добавляют одну точку.
5. После ошибки опрос можно повторить; пустые точки не добавляются.
6. Завершение ожидает опрос, не публикует поздние данные, снимает подписки, запрещает новые опросы и освобождает scanner один раз.
7. Освобождённый HardwareScannerService отклоняет чтение до открытия оборудования.

Сборка приложения: **0 ошибок**, при перекомпиляции 85 существующих предупреждений (nullable и Windows API). Зависимости тестов восстановлены из установленного локального кэша.

Проверка GUI через computer-use: Dashboard заполнилась при запуске без повторного перехода; при первом открытии мониторинга уже видна накопленная история CPU/GPU. После закрытия окна процесс SpecMind завершился. После последней коррекции подписок графика тесты снова пройдены, приложение повторно запущено; повторный переход на мониторинг не завершён из-за одновременного пользовательского ввода в окно. Автотесты не доказывают визуальную корректность attach/detach графика.

## Ограничения и следующий этап

Нативный WMI-вызов не поддерживает отмену текущей операцией этого интерфейса: закрытие ожидает его завершения. Недоступная температура CPU всё ещё отображается как 0°C; алгоритмы датчиков на этом этапе не менялись. Реальная генерация AI ещё не подключена — это этап 3.
