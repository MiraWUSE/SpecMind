# Этап 3: локальный AI

Интерфейс AI использует Qwen2.5-3B-Instruct Q4_K_M через LLamaSharp на CPU. Демонстрационная задержка и тестовый runtime удалены. AIViewModel находится в Modules/AI/ViewModels.

## Поведение

- Модель загружается при первом запросе. Отсутствующий файл не блокирует запуск приложения: чат показывает понятную ошибку.
- AI получает копию текущего HardwareInfo и историю успешных сообщений. Системное приветствие, ошибки и незавершённые ответы не попадают в контекст.
- PromptBuilder формирует ChatML, экранирует управляющие маркеры и при переполнении контекста удаляет старые пары сообщений. Текущий вопрос добавляется один раз.
- Веса остаются загруженными между запросами. Для полного prompt с историей каждый запрос создаёт чистый контекст, чтобы не дублировать KV-состояние.
- Загрузка и генерация выполняются вне UI-потока. Пользователь может отменить запрос. Закрытие приложения отменяет генерацию и ожидает освобождения native-ресурсов.
- Интерфейс показывает полный готовый ответ. Потоковый API сохранён, посимвольный вывод в UI пока не включён.

## Запуск

Поместить `qwen2.5-3b-instruct-q4_k_m.gguf` в `Models` рядом с исполняемым файлом (при локальной сборке файл из каталога проекта Models копируется в output). Файл модели исключён из Git. Путь ModelsDirectory можно изменить в конфигурации AI. Для генерации не нужен внешний AI API.

## Ограничения

Автозагрузка GGUF и посимвольный вывод остаются дальнейшими задачами. Ответы модели требуют проверки. Недоступные датчики нельзя интерпретировать как реальные нулевые температуры: в prompt это явно указано. Существующая проблема отображения температуры CPU отдельно остаётся открытой.

Формат диалога: [официальный tokenizer Qwen](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct/blob/main/tokenizer_config.json). Runtime: [LLamaSharp](https://github.com/SciSharp/LLamaSharp).
